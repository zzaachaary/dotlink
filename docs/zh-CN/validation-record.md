## 2026-10-09：原生快捷指令检查点

2026-10-08，隔离的 Mac 原生测试副本向临时本机回环接收器发送了两次合成通知请求、一次使用 Mac 电池动作的请求。三次均通过现有事件校验器、JSON Content-Type 和占位 Authorization 校验。通知中的引号、换行、反斜杠、中文及 emoji 保持完整；电量是 JSON 数字，充电状态是 JSON 布尔值。这些检查未连接已部署的 Bridge 或 dot，也未执行 iPhone 自动化。

首次通知从事件时间到本机收到约 47 秒，复测不足一秒；充电请求约 44 秒。首次执行较慢的原因尚未查明。事件时间仅精确到秒，因此这些观察不是精确的网络延迟测量，也不能证明稳定性。

2026-10-09，iPhone 镜像显示通知和充电工作副本已同步。通知副本保留了通知属性变量和两项导入问题，手机上可见中文 URL 指引。Mac 复制后触发器缺失，因此在 iPhone 上补入原生 Notification 自动化触发器，来源 App 仍未配置；原始手机母版保持完整。这是编辑器检查，不是真实通知触发结果。

充电副本已在 iPhone 上配置为 `Connects or Disconnects`，并确认自动化开关关闭。另在 iPhone 上复制出独立的 Focus 工作副本，配置 `Do Not Disturb / Is Turned On or Off` 触发器并明确停用。它继承的充电请求内容尚未改成完整的 Focus 实现，不能作为 Focus 模板运行。编辑器中 Get Current Focus 的说明为返回当前开启的模式，无模式开启时返回空值；仅凭此动作不能确定刚刚关闭了哪个模式。触发输入及正确的开启／关闭字段绑定仍待验证。

Focus 请求内容制作、导出及签名产物、独立导入、通知／充电／Focus 真实执行，以及对应的 dot 处理仍待完成。本次原生编辑器检查未重新编译或重复完整集成套件。

## 2026-10-10：Charging 真机闭环与实验性 Beta 决定

原充电自动化关闭期间，已填入本人配置的重新导入 Charging 副本完成真机测试。四条电量／充电记录的时间和值与所有者 dot 画面一致，支持本轮 iPhone → Bridge → dot 展示通过。不据此保证冷启动或延迟；画面无 event_id，未独立核验逐事件回调 ACK。测试后原自动化恢复、四份验收副本全部关闭。

定向只读对照原 Notification Bridge、共用上传器、Device Status、Focus On／Off 与发送器：事件外层、各模块 payload 字段、POST 接口约定和设备 Bearer 认证保持一致。旧版调用共用快捷指令、上传器以 File 模式提交 Shortcut Input 并显式声明 application/json；发布版将原生 JSON 请求放进独立模板。两者并非逐动作相同。公开通知文件明确读取原生 App／Title／Body 属性；旧命名 event 变量的具体属性未由 Mac UI 展示，不能声称已逐属性完全比对。此前合成通知原生请求验证了 JSON 与转义，不代替延后的真实通知测试。

四份签名文件哈希未变，本次未改生产运行逻辑或依赖，四份导出的静态协议断言均通过。最终发布工具定向测试 11/11；此前完整基线为51/51、runtime 6/6，属于不同运行，不合并宣称重新跑过完整套件。
